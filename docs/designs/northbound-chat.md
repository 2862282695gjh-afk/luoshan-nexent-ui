# 北向接口园区对话页面

## Context

将 UI 规范 02 的 PC 对话界面实现为可独立启动的前端，使用用户提供的 Nexent 2.5.1 北向接口文档。附带文档作为接口资料，不作为额外执行授权。工作区未指定目标前端仓库，使用独立目录 `luoshan-nexent-ui`。既有 Nexent 仓库含用户未提交变更，不修改。

## 关键定义

真实模式：服务端已配置 API Key，对话与会话请求调用真实服务。演示模式：浏览器中独立数据集和明确标识的本地示例。两者的 ID、消息和历史不能混用。当前 Agent 仅支持纯文本对话，页面不提供附件上传；历史消息可以展示服务端已有的附件名称。conversation_id 由服务端生成，Agent 以已发布名称寻址。

## 架构与数据流

Vue 页面 → 同源 `/nb/v1` 代理 → 已配置 Nexent 北向服务。代理仅提供允许的业务接口；API Key 不下发浏览器。Vite 中间件和生产 Node HTTP 服务共享代理。页面通过 POST fetch 读取 SSE，首事件建立会话，正文增量实时渲染，final_answer 替换已显示的增量文本。停止时先中断浏览器读取、结束本轮 UI 状态，再异步调用后端停止接口；每轮由独立运行对象隔离，旧流迟到收尾不会覆盖新轮。未取得服务端 ID 时只能停止本地读取并提示服务端状态未知。

## 设计决策

[ADR 0001](../decisions/0001-independent-northbound-ui.html)：独立 Vue 工程与同源代理。视觉以用户提供图片为准，沿用颜色、布局和对话层级；补充一个低干扰工具栏放置连接配置及状态。Markdown 使用 DOMPurify 消毒，不执行上游 HTML 脚本。演示内容不声称查询真实园区数据。

## 边界情况

- 首次请求无 ID，续聊携带相同 ID；每次用户发送分配唯一幂等键。
- final_answer 作为最终完整答案替换，不追加；未知事件忽略。error / agent_error 保留为运行过程提示，继续读取；后续完整答案可恢复成功状态，结束时仍有未恢复错误则报告失败。
- agent_finish 也可能表示子智能体完成，不作为传输结束标记。读取到 EOF 或 [DONE] 后评估结果；EOF 无完整答案时报告断流。
- UTF-8 多字节、跨 chunk 的 CRLF、多行 data、注释及 EOF 均受测试。
- 中文 IME 合成期间 Enter 不发送。会话切换中的过期历史响应不覆盖当前选择。
- 生成期间禁止切换会话与连接，避免消息归属混乱。
- 模型列表失败可降级默认模型；健康/智能体/会话请求失败保留明确错误。
- 发送请求仅包含文本，不提交附件；历史记录中的附件名称仅用于展示。
- 北向文档没有删除接口；删除会话现通过主 API 接入，执行双身份归属校验并提示关联定时任务影响，见 [删除会话](../delete-conversation.md)。非 AI 导航没有业务接口，保留门户占位显示并禁用。

## 性能（DFX）

流式响应不缓冲；代理尊重背压；关闭连接释放上游。180 秒空闲超时与启动超时提供错误反馈。首次加载并发请求健康、智能体与会话列表。演示历史最多保存 50 个会话，真实历史不存浏览器。小屏折叠侧栏，历史和回复区域分别滚动，输入框固定可见。

## 契约改动

不修改 Nexent 服务端契约。增加应用自身只读 `/api/config`，返回 configured、automationConfigured、conversationDeleteConfigured 等配置状态，以及 automationAuthMode、automationAgentId、agentName 与 service；不返回 API Key、用户 JWT 或服务端凭据。代理以单用户实例为界；多租户门户部署需复用门户身份验证和用户凭据映射。

## 测试与验证

TypeScript 校验、生产构建、Vitest 协议/代理测试、Playwright 浏览器交互测试及桌面/移动截图。真实服务联调取决于用户提供服务地址、已发布 Agent 与本地 API Key 配置。

### 2026-09-08 修订协议适配

统一 HTTP 错误解析同时兼容顶层 message、AppException 的 code/message/details、FastAPI 的 detail 校验数组及旧 detail 字符串/对象。413 和 422 提供中文类别；校验数组仅展示字段路径和 msg，不回显 input 或完整请求。ApiError 保留状态码、业务 code 与 details，页面继续使用文本插值显示 message。非 JSON 或异常结构采用状态码提示兜底。问答失败保留草稿，不自动重发。

模型选择严格要求 model_type=llm 且 connect_status=available；字段缺失或状态未知不加入选择器，仍允许使用 Agent 默认模型。该修改沿用 ADR 0001 的代理与前端分工，无新增架构。

验证：20 项接口/代理单元测试通过，覆盖三种实际错误格式、旧格式、无效结构、HTML 网关错误、聊天启动失败不重试与模型筛选；TypeScript 校验和生产构建通过。7 项浏览器回归通过，覆盖 401/413/422 具体原因、草稿恢复与发送按钮恢复。

### 2026-09-08 Windows 首页 403 修复

生产静态服务原先用 file.startsWith(root + '/') 判断目录边界，Windows 的 resolve 返回反斜杠路径，导致合法首页与资源返回 403；北向 API 不经过该检查，因此健康和智能体列表仍可访问。改用 node:path.relative、sep 与 isAbsolute 判断目录边界，保留对父目录及同名前缀兄弟目录的拒绝。新增 5 项路径回归，分别覆盖 POSIX 与 Windows 路径、中文目录、首页、资源及越界路径。25 项单元测试及生产构建通过。Windows 路径语义使用 node:path.win32 验证，尚未在 Windows 主机实机启动；此修复不新增平台启动脚本。

### 2026-09-20 流式工具报错后继续接收

原先事件回调收到 error / agent_error 直接抛异常，触发 SSE reader.cancel，导致后端仍在执行、前端却停止显示。现在错误放入可展开的“运行过程提示”，不取消读取；只有实际连接异常、用户停止、EOF 或 [DONE] 结束读取。最终答案替换增量内容并解除此前的运行错误；若最终答案之后再次报错，则结束时仍提示未收到后续完整结果，不误报成功，不自动重发。

本地 Nexent SDK 的 core_agent.py 将 agent_finish 用于子智能体结束，nexent_agent.py 也会在步骤失败时发 error 后继续循环。因此不再以 agent_finish 截断整个流。model_output_deep_thinking 归入思考过程，后续增量思考仍实时更新。

验证：35 项单元测试、17 项对话浏览器测试和生产构建通过；PC / 手机均用分段受控流验证“工具失败 → 子智能体结束 → 后续思考与增量 → 最终答案”，无需刷新、不重发。另覆盖错误后 EOF、错误后 [DONE]、最终答案后报错和无最终答案的断流。

当日本地连接检查：前端 5180 和北向健康接口正常；智能体列表 401 的底层原因是 PostgreSQL 5434 无法连接。Docker 已启动，但旧数据库容器的 init.sql 挂载失效、原数据目录为空，未初始化新库或修改凭据。此前配置的内网北向服务连接超时，真实对话联调需恢复原数据库或提供当前可达服务。

### 2026-09-28 停止后续聊时序

页面停止交互改为与 Nexent 原生聊天页一致：立即 `AbortController.abort()` 旧浏览器流，保留服务端会话 ID，在后台调用停止接口，并允许用户继续输入和发送。每次发送使用独立 `ChatRun`；只有当前运行可以写入全局流式状态、错误、会话选择和超时提示，避免旧流的延迟 `finally` 将新一轮误标为已结束。

真实 Docker 服务复现了 v2.5.1 的 reservation-to-register 竞态：停止请求可能发生在 reservation 已建立、真实运行尚未注册的窗口。服务端返回停止 HTTP 200 后，首轮仍占用会话，第二轮以 HTTP 200 + 单个 SSE `error` 返回 `Rejected concurrent agent run`。这不是页面流式解析问题；完整根因、后端修复方向和验收条件见 [停止后继续对话](../stop-resume.md)。
