# 删除会话

PC 会话行右侧、手机历史列表中新增垃圾桶按钮。点击后显示会话名称和确认弹窗，默认焦点在“取消”；只有点击“确认删除”才发出请求。生成回复或删除处理中禁止再次删除。主 API 未配置时，真实会话的删除按钮禁用并提示配置。

## 行为

- 真实会话调用主 API 删除会话及消息。Nexent 同时软删除关联定时任务并取消相关运行，确认弹窗明确提示。页面不提供恢复入口。
- 仅在服务端返回 code=0、data=true 后移除记录。删除当前会话回到新对话；删除其他会话保留当前正文和输入草稿。
- 失败或结果不确定时保留记录，不重试，当前弹窗禁止再次确认，提示刷新历史及任务列表核实。
- 演示模式只删除本机演示存储，不调用后端；存储失败保留页面记录，删除最后一条后刷新也不会重新填回示例。

## 连接与归属校验

复用 NEXENT_MAIN_API_URL、NEXENT_USER_TOKEN、NEXENT_AUTOMATION_AUTH_MODE，无新增配置项。JWT 与北向 access_key 继续隔离；显式 speed 模式沿用后端默认开发用户。两套连接应指向同一 Nexent 实例和同一用户。

前端 DELETE /api/conversations/{id} → 同源代理 → 主 API DELETE /conversation/{id}。代理只开放单条正整数 ID 删除，不开放批量删除；仍校验 Origin / Sec-Fetch-Site。

部分 Nexent 版本的删除服务仅把 user_id 用于更新追踪，没有在删除语句中检查归属。因此代理每次操作前，从北向与主 API 分别读取当前凭据的会话列表，要求目标 ID 同时可见，否则不发送删除。主 API 列表固定携带 today_start_ms=0、week_start_ms=0，不设 limit 以读取所有归属记录，兼容旧版 data[] 与新版 data.items。浏览器传入的租户参数不转发。上游重定向、无效格式、超时或超过 4 MiB 的列表均拒绝执行删除；不会自动降级为直接删。

## 验证

53 项单元测试、25 项聊天与删除浏览器测试、TypeScript 检查和生产构建通过。覆盖双身份归属验证、凭据隔离、网关前缀、缺配置、无效 ID、跨域拒绝、未确认成功不重试、PC / 手机确认取消、删除当前 / 其他会话，以及演示存储失败与空列表恢复。

真实联调专门新建空白会话“删除功能联调测试-413162b0”（ID 22），通过前端确认删除，后端返回 HTTP 200、code=0、data=true，刷新和重新读取北向列表均确认该测试记录已消失。未删除原有业务会话，未创建或取消真实业务定时任务。
