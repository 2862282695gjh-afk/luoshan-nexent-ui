# 思考、工具调用与回答分区

实时对话分成三个区域：可折叠的“思考过程”、可折叠的“工具调用”和独立回答正文。沿用现有 PC / 手机布局，生成期间展开过程，流结束后折叠；用户可自行展开查看。模型生成的代码放在思考区的“生成的代码”中，实际执行参数和返回日志放在工具卡片中。

## 事件对应

| Nexent 事件                                                    | 展示位置                                                       |
| -------------------------------------------------------------- | -------------------------------------------------------------- |
| reasoning / model_output_thinking / model_output_deep_thinking | 思考过程，增量追加                                             |
| model_output_code                                              | 思考过程 → 生成的代码，不写入回答                              |
| tool / tool-call                                               | 独立工具卡片，显示名称与调用参数                               |
| parse                                                          | 兼容旧版 Python 解释器调用，代码作为调用参数显示               |
| execution_logs                                                 | 对应工具卡片中的返回结果                                       |
| error / agent_error                                            | 保留运行过程提示；有 tool_call_id 时同时标记对应工具，不关闭流 |
| agent_finish / 带子智能体标记的 final_answer                   | 子任务结果卡片，不替换主回答或终止流                           |
| model_output / 主智能体 final_answer                           | 回答正文；最终答案整体替换增量内容                             |

工具日志优先按 tool_call_id 与 invocation_id / agent 身份归属。同一个稳定 ID 的未知结果会单独显示为执行记录，不挂到另一个并行工具上。旧版本没有调用 ID 时，按对应作用范围内最近一次工具调用关联。没有收到日志的调用在结束后标记“未返回结果”，用户停止后标记“已停止接收”；“已返回”仅代表收到日志，不等于业务执行成功。原有工具报错后继续接收、最终答案替换、无重试规则保持不变。

## 历史限制

当前已检查的北向会话历史 content 是纯文本，未返回完整的工具、参数、日志和推理事件。前端不会从正文猜测或伪造过程，也不把真实对话过程写入浏览器持久化存储。因此当前实时对话能查看这些分区，刷新或重新加载历史后只能展示该接口实际返回的正文。完整历史回放需要后端在当前北向身份下提供结构化过程。

## 验证

45 项单元测试、19 项对话浏览器测试、TypeScript 检查和生产构建通过。覆盖并行调用关联、未知调用 ID、不重复拼接最终正文、子智能体结果隔离、旧版 parse、报错后继续推理以及停止 / 缺结果状态。PC 和 390px 手机截图检查通过，无横向溢出。事件交互使用契约模拟验证，未执行真实设备工具操作。
