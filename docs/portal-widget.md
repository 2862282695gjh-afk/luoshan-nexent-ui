# 门户悬浮对话窗

## 页面入口

- `/`：完整的独立对话页面，保留历史会话、定时任务等完整页面能力。
- `/portal-demo/`：模拟的罗山科技园门户，用于查看顶部门户布局、悬浮球和小窗交互。通知、日程、OA 与快捷应用均为演示数据，不连接真实门户业务接口。
- `/embed/`：供门户嵌入的紧凑对话页面。加上 `?chrome=0` 会隐藏嵌入页自身的顶栏，适合由门户小窗提供标题和关闭按钮。

`/portal-demo/` 中的悬浮球打开的就是 `/embed/?chrome=0`，可作为集成效果参考。

小窗输入框上方提供一排 Can Do List：知识问答、数据分析、预测预警、巡检上报、运维报告，与完整对话页共用测试用例。鼠标悬停或点击能力项可向上展开纵向用例列表，点击用例仅填入草稿，用户可编辑后再发送。列表在对话开始后仍保留；断开连接或生成回复时暂不可选。

## 在正式门户中嵌入

正式门户可继续使用现有技术栈，无论是传统页面、Vue、React 还是其他框架，只需在悬浮窗内容区域放入本服务的 iframe。例如：

```html
<iframe
  src="https://ai.example.com/embed/?chrome=0"
  title="罗山智能助手对话"
  allow="clipboard-write"
></iframe>
```

门户负责悬浮球、窗口位置、最小化和关闭等外围交互；iframe 只负责对话。请使用部署后的 HTTPS 域名，不要把 Nexent `access_key`、用户 JWT 或其他凭据拼进 URL、HTML 或浏览器请求。

浏览器内的 iframe 请求会先回到 AI 助手自己的同源 Node 服务，再由该服务转发到 Nexent。`NEXENT_API_KEY` 只保存在该服务的 `.env` 中，门户前端不需要也不应拿到它。

小窗标题栏的「完整对话」会在新标签打开 AI 助手主页面，并保留当前小窗；它不会主动把小窗的当前 UI 会话切换或迁移到主页面。若门户和 AI 助手不在同一站点，该按钮应使用 AI 助手服务的绝对主页面 URL，例如 `https://ai.example.com/`，不能写成门户自身的根路径 `/`。

## 允许门户嵌入

生产服务只在嵌入页响应上设置 `Content-Security-Policy: frame-ancestors`。默认只允许本站嵌入；外部门户需要在 AI 助手服务的 `.env` 中增加门户**源**：

```dotenv
EMBED_ALLOWED_ORIGINS=https://portal.example.com https://portal-test.example.com
```

多个源可以使用空格或逗号分隔。配置的源会附加到 `'self'`；只接受 `http` 或 `https` 的完整源，例如 `https://portal.example.com`。改动 `.env` 后重启 Node 服务。该 CSP 用于限制可嵌入页面的来源，门户自身仍应在入口实施登录和访问控制。

## 小窗会话的保留范围

示例悬浮窗首次打开后会隐藏 iframe，而不会销毁它。因此用户最小化或关闭小窗再打开时，当前 iframe 内存中的消息和会话 ID 会保留。

嵌入页不会请求、展示或恢复历史会话，避免共享服务凭据下把其他用户的历史带入门户。刷新 iframe、刷新门户页面或由门户主动销毁 iframe 后，当前 UI 会话会丢失并从新会话开始；这不会删除 Nexent 服务端可能已经保存的会话数据。

## 验证与当前限制

本次真实服务联调确认：小窗可以连接已发布的“罗山AI运维助手”，发送问题并收到最终回复；关闭再打开可保留当前对话。自动化测试覆盖最终答案替换、工具错误后的恢复、多轮会话 ID、两种紧凑尺寸，以及停止后旧流不会覆盖新一轮。

当前部署的后端在停止后续聊时仍实测出现提前断流，因此真实停止续聊尚未通过验收。已有后端停止时序问题及修复建议见 [停止后继续对话](stop-resume.md)；本次门户演示没有修改后端。
